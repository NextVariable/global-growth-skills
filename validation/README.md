# 合集验证

合集保持五个独立仓库；`catalog.json` 指向各自公开版本。五个版本均已公开，各自维护方法与测试。合集不会自动纳入本地尚未推送的提交。

安装工具的 9 项测试覆盖选择不存在的 Skill、拒绝覆盖已有目录、第二次下载失败前不改目标、完整复制安装单元、目录穿越输入、缺少许可、格式错误清单、机器生成缓存排除、真实 Git checkout 不执行下载仓库里的钩子。审查曾发现钩子隔离目录放在下载树内会被仓库内容替换；已改为下载树外真实空目录，并通过真实 Git 测试复现和保护该失败路径。

五个指定版本已实际从 GitHub 下载到一个全新临时目录，安装完成。安装不执行任何 Skill 运行脚本，只复制完整安装单元；用户自行使用时仍应了解相应 Skill 的能力和授权范围。后续重复安装面对已有同名目录会停止，不合并旧文件。跨平台由 GitHub Actions 分别运行 Linux、macOS 和 Windows 检查。

另使用一个独立新模型上下文串联第三、第四、第五部分，处理已有市场判断和内容资产中的价格、能力与产能变化。见[输入](integration/input.md)、[原始输出](integration/output.md)和[运行记录](integration/manifest.json)。输出保留已签客户的旧价格，未把未接受的旧报价自动当作已失效；修正自动导出与无证据省时数字，保持创作者未签约状态，并暂缓混入调价的首页转化实验。维护者语义审阅认为交接符合任务，但这是合成场景，没有真实外部动作或业务收益。

该交接运行加载的第三部分入口早于服务时段澄清；它不用于证明第三部分修改后的全部方法。第三部分另在新上下文完成三场景复测，详情在其独立仓库。本合集没有把一次串联测试包装成五个 Skill 全量验收或竞品胜出。

自动检查不运行模型，不验证真实成交或增长。模型试用、计算测试、安装验证和实际客户效果分别保留证据边界。
