## English

### 1. What V1.0 is

Global Growth Skills is a set of five independent Agent Skills for international go-to-market work, plus an optional local harness that can run them as one workflow. Start with a product brief — what the product does, which decision is open, who it serves, what evidence exists, and what is authorized. Then use only the skill that matches the current decision.

V1.0 is deliberately bounded:

- It produces **market decisions, drafts, operating packages, experiment plans and post-run reviews** for human review.
- It does **not** automatically acquire customers, close deals, publish content, contact people, write to a CRM or spend ad budget.
- No real customer adoption, conversion or revenue outcome is claimed.

### 2. The five skills

| Decision at hand | Independent skill | Typical output |
|---|---|---|
| Which market to enter, whom to serve first | `global-gtm-strategy-skill` | Customer choice, competitive trade-offs, entry path, next validation |
| How customers understand the value | `global-growth-content` | Positioning, landing page, article, README, social/video scripts |
| How to bring suitable users in | `global-launch-acquisition` | Channel choice, launch package, partnerships, schedule, execution checks |
| How to move users to purchase and renewal | `global-sales-retention` | Customer actions, pilots, follow-up, activation, renewal, expansion |
| What to do next and whether results justify continuing | `global-growth-experiments` | Validation design, measurement, guardrails, results, continue/stop decision |

Each skill lives in its own repository and is installation-independent. The catalog pins the five revisions used by the harness; installing one skill never requires the other four.

### 3. Install and run

**Single skill.** Follow that repository's `npx skills add` command. Each repository contains its own task examples and license.

**The whole set (version-pinned).** Requires Git and Python 3.10+:

```sh
git clone https://github.com/NextVariable/global-growth-skills.git
cd global-growth-skills

# preview only
python3 scripts/install.py --dest ~/.agents/skills

# install after reviewing the preview
python3 scripts/install.py --dest ~/.agents/skills --install

# or install a subset
python3 scripts/install.py --dest ~/.agents/skills \
  --only global-launch-acquisition global-sales-retention --install
```

Existing directories are never overwritten. The installer downloads every selected revision first, then copies complete units with their licenses and never executes downloaded scripts. Pinned revisions are in [catalog.json](../catalog.json).

**Harness.** The harness stores project context, evidence, task state and drafts in a SQLite file outside the repository:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements-harness.txt
```

Check the local runtime at any time with:

```sh
python -m harness --db "$db" doctor
```

### 4. A complete GTM workflow

Run the offline example first. It proves installation, planning, resumption and export without any model call or network research:

```sh
work="$(mktemp -d)"
db="$work/project.sqlite"

python -m harness --db "$db" init examples/harness/project.json
python -m harness --db "$db" start demo --goal "完整 GTM"
python -m harness --db "$db" step demo
python -m harness --db "$db" resume demo

# a price change invalidates only the dependent drafts
python -m harness --db "$db" change examples/harness/price-change.json
python -m harness --db "$db" resume demo

python -m harness --db "$db" export demo > "$work/gtm-package.md"
```

The same shape runs against a real model host when one is authenticated:

```sh
python -m harness --db "$db" start public --execution model --goal "full workflow"
python -m harness --db "$db" step public --model "$GTM_MODEL" --checkouts-dir "$work/pins"
python -m harness --db "$db" resume public --model "$GTM_MODEL" --checkouts-dir "$work/pins"
python -m harness --db "$db" export public --format json > "$work/gtm-package.json"
```

Partial scopes are explicit: `start channel --stages launch` runs acquisition only; `--stages strategy launch` runs the short chain. Inspect progress, evidence and receipts with `status RUN`, and evidence coverage with `audit RUN`.

When the model proposes a different threshold, sample size or window, do not let it overwrite the contract. Submit an operator revision instead:

```sh
python3 -m harness --db "$db" revise-decision RUN patch.json \
  --reason "Operator approved a wider pilot" --expected-revision 1
```

### 5. Evidence, decision contract and recovery

**Provenance classes.** Every factual statement is classified:

| Class | Meaning | Citation requirement |
|---|---|---|
| `operator_input` | Facts, budgets, targets, approved constraints supplied by the operator | None; still never auto-`verified` |
| `external_evidence` | Claims mapped to a valid source by verbatim fragment | Required |
| `inference` | Reasoned but unconfirmed assumptions | Not presented as fact |
| `proposal` | Suggestions the model raises but cannot approve | Marked unapproved |

A model cannot self-report `operator_input` or approval. An approved 0 USD or 100 USD budget needs no webpage; an unsupported competitor price, market size or paid-customer count still fails the gate. Missing external claims produce `incomplete_evidence`; verbatim-but-unreviewed claims produce `needs_evidence_review`; structural delivery gaps produce `needs_quality_review`.

**Decision contract.** The strategy stage emits a versioned `contract`: objective, primary metric and denominator, unit, target value, comparator, sample size, independence conditions, observation window, budget, evidence references, assumptions and approval status. Unknown values stay `unknown`; the model cannot invent thresholds. Downstream stages must copy the `decision_id`, `decision_revision`, `contract_sha256` and every `decided` constraint verbatim. Changing a number, unit, denominator, window, budget or revision fails before the draft is written. Only the operator can approve a revision, and old drafts become stale.

**Recovery.**

| Situation | Command | Behavior |
|---|---|---|
| Normal interruption | `resume RUN` | Reads the committed checkpoint |
| Process exited but state says running | `resume RUN --recover` | Takes over; verify the old process is gone |
| Adapter or host failure | `resume RUN --retry` | Retries the failed attempt |
| Source changed or withdrawn | `change` then `resume` | Only dependent drafts become stale |
| Context value restored | `restore REVISION` | Appends a new context revision; history is kept |

A late response from a superseded attempt is rejected at commit time. Transactions cover completion, citations and drafts together.

### 6. Security boundaries and known limitations

- Codex runs read-only: shell, unified execution, plugins, MCP and web search are disabled; no approval escalation. The harness checks host-reported tool activity.
- GitHub research is fixed to HTTPS GET, rejects redirects, sends no credentials and limits size, time and result count.
- `research-web` fetches one explicit public HTTPS page: private addresses, non-443 ports, credentials, redirects, non-HTML, oversized responses and proxy transport are rejected. DNS is resolved once, the connection is pinned to a verified global unicast IP, and TLS still validates the original hostname. Provider text is untrusted; instruction-like text is blocked from citations and prompts.
- Approvals rely on the local POSIX account that owns the private database. There is no remote authentication, multi-user RBAC or production write connector.
- No independent semantic reviewer is connected: verbatim matches remain `unverified`.
- Provenance matching is rule-based; unusual number words, currencies or ambiguous prose need human review. Free-text contradictions are not auto-blocked.
- Real publishing, outreach, CRM writes, ad spend, customer adoption and revenue are not executed or measured.

### 1. 产品介绍

Global Growth Skills 是五个独立的海外增长 Agent Skill，加一个可选的本地编排器。输入一份产品背景——产品做什么、这次要决定什么、服务谁、已有什么证据、被授权做什么——再选择与当前决策匹配的一个 Skill。

V1.0 的边界是明确的：

- 产出**市场判断、成稿、操作包、实验方案与复盘决定**，供人审阅。
- **不**自动获客、不自动成交、不自动发布、不主动触达、不写 CRM、不消耗广告预算。
- 不宣称真实客户采用、付费转化或收入增长已经发生。

### 5. Evidence、Decision Contract 与恢复机制

**来源分类。** 每条事实按四类记录：

| 类别 | 含义 | 引用要求 |
|---|---|---|
| `operator_input` | 操作者提供或批准的项目事实、预算、目标与约束 | 不需要外部引用，但不会自动变成 `verified` |
| `external_evidence` | 通过逐字片段映射到有效来源的断言 | 必须 |
| `inference` | 有依据但尚未证实的推断 | 不得当作事实陈述 |
| `proposal` | 模型提出但不能自我批准的建议 | 明确标为未批准 |

模型不能自报 `operator_input` 或审批。已批准的 0 USD、100 USD 预算不要求网页引用；无依据的竞品价格、市场规模、付费客户数量仍会被门禁拒绝。缺少必要外部 claim 时包为 `incomplete_evidence`；逐字命中但未语义复核为 `needs_evidence_review`；交付结构缺口为 `needs_quality_review`。

**决策契约。** 战略阶段输出带版本的 `contract`：目标、主指标与分母、单位、目标值、比较符、样本量、独立条件、观察期、预算、证据引用、假设与审批状态。未知值保持 `unknown`，模型不能补造阈值。下游必须逐字复制 `decision_id`、`decision_revision`、`contract_sha256` 和所有 `decided` 约束；改动数值、单位、分母、时间窗、预算或复用旧 revision，会在写入草稿前失败。只有操作者能批准修订，旧草稿随即失效。

**恢复机制。**

| 情况 | 命令 | 行为 |
|---|---|---|
| 正常中断 | `resume RUN` | 读取已提交检查点 |
| 进程已退出但状态仍在运行 | `resume RUN --recover` | 接管；先确认原进程已退出 |
| 适配器或宿主失败 | `resume RUN --retry` | 重试失败尝试 |
| 来源改动或撤回 | `change` 后 `resume` | 只让依赖该来源的草稿失效 |
| 恢复上下文旧值 | `restore REVISION` | 追加新版本，保留历史 |
| 旧尝试迟到 | 自动拒绝 | 提交边界拒绝被取代的响应 |

完成状态、引用和草稿在同一事务提交。

### 6. 已知限制与安全边界

- 模型宿主只读：关闭 shell、统一执行、插件、MCP 与网页搜索，不提供审批升级；代码检查宿主报告的禁用工具活动。
- GitHub 研究仅固定 HTTPS GET，拒绝跳转，不发送凭证，并限制响应大小、时间与结果数。
- `research-web` 只抓取操作者显式给出的单个公开 HTTPS 页面；拒绝私网、非 443 端口、凭证、重定向、非 HTML、超限响应与代理传输。DNS 只解析一次，连接固定到已验证的全局单播地址，TLS 仍校验原主机名。页面文本视为不可信，指令式内容不进入引用或提示词。
- 审批依赖拥有私有数据库的本机 POSIX 账户；没有远程认证、多人 RBAC 或生产写连接器。
- 没有接入独立语义评审器，逐字命中仍保持 `unverified`。
- 来源分类依赖结构化规则，非常规数字写法、币种或含混表达需要人工复核；纯正文中的矛盾不会自动拦截。
- 不执行也不测量真实发布、触达、CRM 写入、广告消费、客户采用与收入。
