# Global GTM Harness 1.1 — GTM Intelligence

V1.1 在 V1.0 的编排、证据与审批边界上增加市场研究、决策可追溯性和交付质量，不重写 Harness 基础设施。当前分支为 `feat/v1.1-gtm-intelligence`，以 Draft PR 提供审查。

## 新增能力

### 1. 多来源研究

- `harness/providers.py` 统一只读研究 Provider：GitHub、公开网页、Hacker News。
- `research-community` 通过 Hacker News 公共 Algolia API 获取公开讨论快照，记录 URL、观察日期、有效期、标题、分数、评论数和发帖日期。
- 捕获可在离线状态重新校验；来源 ID、URL、摘要或计数被篡改时拒绝。
- 明确边界：分数与评论只代表公开讨论活动，不是需求、采用、付费客户或市场规模。
- 仍保留 SSRF、重定向、TLS、响应体大小、指令注入阻断、来源时效/冲突/去重检查；不获取文章正文，不绕过登录、反爬或付费墙。

### 2. GTM 决策智能

`harness/intelligence.py` 为九个决策领域生成结构化 brief：

- 市场优先级、ICP 分层、竞争定位、价值主张、渠道优先级
- 定价与打包、获客实验、销售资格、激活与留存

每个领域包含问题、状态、候选依据、待解决问题和护栏。缺少候选证据或必要审批时显示 `needs_evidence`。有候选资料的领域进入 `needs_internal_review`，由复核者核对具体引文、声明和商业建议。逐字匹配仅记录文字出处，语义支持和商业验证分别处理。GitHub 仓库元数据和 Hacker News 讨论始终归为 `external_signal`，可用于描述公开活动。Brief 随战略任务传给宿主。JSON 和 Markdown 导出保留来源分类及声明的语义核验状态。

### 3. 交付质量

GTM Package 新增：

- Executive Summary（产品、目标、ICP、预算、证据统计、状态与下一步）
- Market and ICP Research
- Competitive Landscape（仅使用已捕获的 competitor 主题来源；缺失时明确说明）
- GTM Decision Register
- KPI and Measurement Framework（仅来自已批准的合同槽位与结构化 action 指标）
- Action Register

每个 action 必须具备 owner role、前置条件、资源、指标和下一步；缺失时导出包明确要求人工补齐，而不是生成模板化动作。

### 4. Token 与上下文效率

- `prompt_review` 只传递可引用、已捕获、无注入标记的来源，并在固定字符预算内截断与计数。
- `cost-report RUN` 聚合真实 host receipt 的 token、字节、调用次数和耗时；没有批准的价格表时，成本保持 `not_estimated`。

### 5. 宿主兼容

- `harness/host.py` 定义 `TaskInput` / `TaskResult` 与 `HostAdapter` 协议。
- `codex` 与 `fixture` 适配器各自声明工具策略、上下文和 Skill 加载能力，不假设宿主能力相同。
- `host-contract` 输出能力矩阵与交接契约。工作流状态、证据与审批仍由 Harness 持有。

## 结构基准（确定性，非模型评测）

`evals/v1.1/cases.json` 覆盖 AI SaaS、Developer Tools、Smart Hardware 三个公开产品案例。三种模式均为确定性 fixture：

- A `generic_single_agent`：单 Agent 散文式代理
- B `manual_five_skills`：五个 Skill 分别运行、无结构化交接
- C `harness_orchestrated`：完整 Harness

离线结果（质量分为结构/质量评分卡，满分 100）：

| Case | A 质量 | B 质量 | C 质量 | A 完整 action | C 完整 action |
| --- | --- | --- | --- | --- | --- |
| ai-saas | 38 | 43 | 47 | 0 | 4 |
| developer-tools | 32 | 37 | 41 | 0 | 4 |
| smart-hardware | 35 | 43 | 47 | 0 | 4 |

结论边界：

- 这只证明工作流结构、可追溯字段与交付完整性，不证明商业质量。
- 真实模型对比 **NOT TESTED**：本轮未调用付费模型，未产生模型 token/成本数据。
- 真实商业效果 **not measured**：没有客户、收入、留存或转化结果。
- `--live` 会把公开 Hacker News 讨论快照纳入三种模式；讨论热度仍不代表市场规模或付费需求。
